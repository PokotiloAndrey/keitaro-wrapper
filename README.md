# Keitaro Workshop

Обёртка над Keitaro Admin API: FastAPI, SQLAlchemy 2, Alembic, SQLite, HTML и JavaScript.

## Возможности

- Создание кампании с тестовым префиксом, группой, источником и выбранным доменом.
- Первый поток: указанная страна → Google. Замыкающий поток: остальные посетители → оффер.
- Проверка сохранённых потоков до включения кампании.
- Добавление, удаление из потока и возврат офферов, закрепление долей, распределение остатка до 100%.
- Черновики, отмена, применение и повторное чтение результата из Keitaro.
- Защита от повторного создания и конфликтов редактирования, журнал операций.

## Запуск на Windows

Нужен Python 3.12.

1. Запустите `setup.cmd`.
2. В созданном `.env` заполните `KEITARO_URL`, `KEITARO_API_KEY`, `APP_PASSWORD`, `CAMPAIGN_PREFIX`.
3. Запустите `start.cmd`. Скрипт применит миграции и запустит приложение.
4. Откройте http://127.0.0.1:8000. Логин и пароль: `APP_USER` и `APP_PASSWORD` из `.env`.

`KEITARO_URL` — адрес удалённого трекера. Суффикс `/admin` автоматически удаляется. Пароль приложения задаётся отдельно от пароля Keitaro. API-ключ остаётся на сервере приложения. Префикс должен иметь вид `test_фамилия_`; редактор показывает только кампании с этим префиксом.

## Ручной запуск

```sh
python -m venv .venv
```

## После выдачи доступов

1. Убедитесь, что `DEMO_MODE=false`, а ключ принадлежит нужному пользователю и трекеру.
2. Запустите `start.cmd`, чтобы применить миграции, включая `002` для архива офферов. Выполните `check.cmd` или `python -m app.check`. Проверка читает справочники, проверяет локальную БД и не меняет кампании. Код выхода 0 — чтение и конфигурация проверены; 2 — есть недостающие данные.
3. Нажмите «Обновить списки». Если изменились только права, перезапуск не требуется. После изменения `.env` перезапустите приложение.
4. Выберите оффер, группу, источник и домен. Если согласовано использование базового домена трекера, отметьте соответствующий флажок. В этом режиме `domain_id` не передаётся; Keitaro использует настройки по умолчанию. Для проверки этого режима: `python -m app.check --base-domain`.
5. Создайте тестовую кампанию. Проверьте в админке домен, группу, источник и два потока.
6. Через симуляцию трафика проверьте выбранную страну и другую страну. Затем проверьте фактический переход по ссылке кампании.
7. Добавьте второй и третий офферы: доли должны стать 50/50 и 33/33/34. Закрепите 40%: остальные получат 30/30. Примените и сверьте результат в Keitaro.
8. Уберите один оффер, примените, затем верните его. Проверьте отмену черновика и конфликт при изменении потока непосредственно в Keitaro.

Источник обязателен по заданию. Если он отсутствует или недоступен, приложение не подставляет фиктивный ID. Ошибка каждого справочника отображается отдельно; редактор существующих кампаний не блокируется из-за отсутствия доменов или источников.

## Миграции

```sh
python -m alembic upgrade head
python -m alembic current
```

Таблицы автоматически не создаются. Для отката: `python -m alembic downgrade base`. Откат удаляет локальные черновики и журнал; предварительно скопируйте БД. Объекты в Keitaro миграции не изменяют.

## Демо

Установите `DEMO_MODE=true`, отдельный `DATABASE_URL=sqlite:///./demo.db` и свой `APP_PASSWORD`. Примените миграции и запустите приложение. Демо явно отмечено на экране и не обращается к Keitaro. Кампании демо хранятся в памяти и исчезают после перезапуска. Для нового демозапуска используйте новую БД, чтобы старые черновики не совпали с повторно выданными ID.

## Тесты

```sh
python -m pytest -q
```

Проверяются создание потоков, повторные запросы, геокод, доли, черновики, конфликты, частичный сбой, авторизация, базовый домен и недоступные справочники. Тестовый адаптер не заменяет проверку на сервере работодателя.

## Финальная проверка тестовой кампании

После настройки `.env` можно безопасно сверить сохранённую кампанию с Keitaro (только GET-запросы, без изменения потоков):

```sh
python -m app.verify_campaign --campaign-id 211693 --name test_pokotilo_campaign1 --country DE --group-id 9799 --source-id 836 --domain-id 1813 --offer-ids 13972 11733
```

Скрипт проверит имя, статус, группу, источник, домен (если поле возвращается API), два потока, GEO-фильтр, Google-редирект, ID офферов и сумму долей. При несоответствии вернёт ненулевой код завершения. Если Keitaro не возвращает `domain_id`, проверка явно сообщит о необходимости сверить домен в админке.

Это проверка конфигурации по API, а не фактическая симуляция трафика: перед сдачей отдельно проверьте в Keitaro, что посетитель из DE попадает на Google, а посетитель из FR — в поток офферов.

## Ошибки и ограничения

- Кампания создаётся выключенной и включается после проверки потоков. При сбое смотрите журнал: частичный результат сохраняется для проверки. Не повторяйте создание вслепую после сетевой ошибки.
- «Убрать» сохраняет оффер в локальном архиве с долей 0%; при применении его привязка исключается из потока Keitaro. Общий объект оффера не удаляется. «Вернуть» восстанавливает привязку. Последний активный оффер убрать нельзя.
- При повторной загрузке удалённые в Keitaro офферы попадают в локальный архив. Неопубликованный черновик не перезаписывается: сначала примените или отмените его. Закреплённые доли сохраняются после применения.
- Изменённый поток выделяется жёлтым. Отмена убирает неопубликованные добавления и загружает актуальное состояние Keitaro, сохраняя ранее известные офферы в архиве.
- Применение меняет только `offers` потока. Фильтры и лендинги сохраняются.
- Используется один процесс. Между чтением и записью в Keitaro возможна внешняя правка; избегайте одновременного редактирования одного потока.
- Логика редактора сверена с полной расшифровкой видео задания: загрузка потоков, добавление, локальный архив, возврат, отмена, закрепление долей и повторная синхронизация. Финансовые отчёты не входят в редактор; отображаемые проценты относятся к распределению трафика. Реальные запросы и редиректы на версии работодателя требуют приёмочной проверки.
- Запуск рассчитан на localhost. Для публичного размещения необходимы HTTPS и ограничение доступа.
- `.env`, ключи, пароли и БД не входят в репозиторий.

## Проверка интерфейса

Для отдельного DOM-теста нужен Node.js 24 и `jsdom` (`npm install --no-save jsdom`). Запустите приложение в деморежиме с отдельной БД и выполните:

```sh
TEST_URL=http://127.0.0.1:8000 TEST_PASSWORD=your-demo-password node tests/ui/editor.cjs
```

В PowerShell задайте `$env:TEST_URL` и `$env:TEST_PASSWORD`, затем выполните `node tests/ui/editor.cjs`. Тест создаёт демокампанию и проверяет кнопки добавления, применения, удаления, возврата и отмены. Не запускайте его против рабочего трекера.
